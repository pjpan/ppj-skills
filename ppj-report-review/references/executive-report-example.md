# 管理层汇报的形式观察

本参考文件提炼一类方向对齐与体系说明型汇报的表达方法。它提供可选写法，不规定通用目录或评分标准；不要把具体业务主张、分类、术语、指标和图形结构搬到其他材料中。

## 可借鉴的表达方法

- **先给阅读地图。** 开头用短摘要说明讨论范围，让管理层知道接下来会看到什么。若是短会或单项决策稿，摘要可以更短或直接进入待决问题。
- **让标题传递观点。** 章节标题除了标识主题，还提示该节想让听众记住的判断。观点须由正文证据支撑，不能让口号承担论证。
- **按问题推进。** 一段回答一个问题，结尾自然引出下一段。可依照经营逻辑、时间、角色、问题到方案等方式推进，选择最符合材料与听众预期的一种。
- **用图像承载核心逻辑。** 对模式差异、协作关系、能力映射、效果变化和推进范围，先考虑能否让听众通过图看见关系，再读解释。对照可用并列图，协作可用流程或关系图，趋势可用带口径的图表，取舍与覆盖可用矩阵。图形由问题决定；每张图写清要证明的一句话，标注对象、方向或坐标，并在图旁给出读图结论。
- **切换证据形式。** 具体使用适合真实案例，采用情况适合指标，复杂机制适合示意图，效果判断需要与主张相称的数据和方法。文字、图、数据和演示各司其职；不用装饰图代替论据。
- **展示证据的层级。** 访谈与案例说明具体体验和用法，使用数据说明是否被采用，结果数据说明观察到什么变化。评审时逐层追问口径与限制，不把前一层直接推论为后一层，也不把观察到的变化直接写成因果。
- **保留必要的诚实。** 方向、假设、阶段目标、预测和已验证事实分别表述；尚无可靠数字时说明形成判断和验证的路径。

## 使用边界

先判断这次汇报是方向对齐、进展同步、专项评审还是申请决策，再决定是否采用上述形式。不同类型的汇报不必采用相同开头、章数、视觉元素或结尾。涉及成本、效果、因果和推广时，仍须逐一核对证据强度、可比性和外推条件。
