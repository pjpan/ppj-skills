# Executive Blueprint — 按汇报目的组织材料

先判断会议要解决什么问题，再选择结构与表达密度。以下是素材组织方法，不是固定目录；用户有既定模板或合适叙事时，保留它并修复逻辑与证据。

| 汇报目的 | 开头优先交代 | 正文需要支撑 | 结尾落点 |
| --- | --- | --- | --- |
| 方向对齐 | 当前判断、业务变化、需要形成的共识 | 经营逻辑、实践信号、可行路径及尚未验证的前提 | 下一步验证和共识形成方式 |
| 成果或进展 | 阶段结论、目标完成情况 | 真实案例、采用情况、效果证据、偏差原因 | 近期动作与检查点 |
| 专项决策 | 待决问题、建议选项 | 备选方案、收益成本、关键风险和取舍 | 决策事项、责任和时限 |
| 技术体系 | 能力对业务结果的作用 | 机制、约束、质量/成本/稳定性证据与复制条件 | 能力缺口及优先级 |

同一份材料可以兼具多种目的，但应有主目的，避免章节各自讲得完整而整篇没有焦点。

## 论证和叙事

1. 提炼一个读者应记住的核心判断，确认它有业务对象、时间范围和证据支撑。
2. 让每节只回答一个问题；可按问题到方案、过去到未来、角色到组织或局部到整体推进。过渡处说明前一节为何引出下一节。
3. 依据证据强度安排论断：访谈和案例可支持具体体验与用法，采用数据说明使用情况，同口径结果数据说明观察到的变化；因果与可推广性另需相应验证。不要跳层推论。
4. 需要呈现结构关系时，优先考虑图像：明确图的观点式标题、对象、连线或坐标含义、数据口径和一句读图结论。重构稿适合用图时给可直接使用或渲染的图稿；对复杂图，删去与本节判断无关的节点。
5. 收束到与本次汇报目的相称的动作；不为方向对齐稿编造审批请求，也不让决策稿停留在“继续探索”。

## 四类常见问题

| 问题 | 表现 | 改法 |
| --- | --- | --- |
| 自嗨式汇报 | 从工作清单起笔，读者不知道为何关心 | 补足业务对象、问题与阶段判断 |
| 层级混乱 | 把目标、收益、功能和动作排成同级条目 | 统一同层分类标准，分清结果与手段 |
| 空中楼阁 | 远期蓝图缺少已验证的起点和约束 | 交代先做哪里、为何选择、怎样验证 |
| 逻辑断层 | 章节各自成立，缺少推进关系 | 用问题或因果过渡串起各节，必要时调整顺序 |

这些名称只在贴合原稿时使用，不为凑数逐项套用。

## 一页纸可选骨架

```markdown
# [项目 / 议题]：[本次最重要的判断或待决问题]

- 汇报目的：[对齐 / 同步 / 决策 / 其他]
- 当前判断：[一句话，注明适用范围]
- 关键依据：[两三项最能支撑判断的事实及来源]
- 关键图：[要表达的关系或变化；观点式标题；数据口径]
- 未知与约束：[尚缺什么证据、哪些条件会改变判断]
- 下一步：[行动、责任人、时间和检查方式；如需决策则列出选项]
```

## 重组零散笔记

先按「事实 / 目标 / 假设 / 预测」标注素材，再找核心判断与证据链。删除重复或不服务于主目的的内容，把最难用文字解释的关系改成图示草案。最后检查标题能否独立串出整篇逻辑，并逐项核对数字与图表口径。
