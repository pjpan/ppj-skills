# Executive Blueprint — 管理层汇报的四阶段结构

把零散材料重组为面向管理层的汇报时，默认使用下面的四阶段结构。用户已有强制模板时，把内容映射到该模板；按项目阶段缩减不适用部分，不把日常进展汇报扩成平台战略。

每个阶段同时承载两条线：**逻辑（金字塔）** 回答「论证是否成立」，**叙事（故事）** 回答「听众为什么愿意继续听」。

## 阶段 1 — 战略愿景与核心价值（Why）

| 线 | 要求 |
|---|---|
| 逻辑（自上而下） | 开头直接给出突破性价值，再做 MECE 的价值拆解。价值拆解建议固定为三个互斥维度，例如 **规模/数量、精度/质量、速度/效率**；不要四个以上，也不要让两个维度讲的是同一件事。 |
| 叙事（SCQA） | 依次交代：现状与基线（S）→ 市场或技术变化带来的矛盾（C）→ 由此产生的关键问题（Q）→ 本方案作为回答（A）。先构建张力，再给出答案。 |

价值必须先于挑战出现。开篇若先讲困难、风险与资源缺口，听众的判断会停在困难上，听不到「为什么值得做」。

**数量级表述的证据门槛**：可以用数量级语言描述突破性，但「10x」必须由 baseline、口径和数据支撑；证据不足时写明这是假设，并给出验证方式，不默认承诺 10 倍收益。

## 阶段 2 — 战略聚焦与 MVP 验证（Where / How）

| 线 | 要求 |
|---|---|
| 逻辑（取舍） | 说明为什么**这个具体场景**是起点：可行性、验证成本、代表性、对后续推广的杠杆。 |
| 叙事（转折点） | 宏大愿景从小处开始。展示已经取得的局部胜利，用早期数据或信号建立组织信心，再谈放大。 |

未验证时，写清实验范围、指标、成功阈值与下一步，而不是把「已验证」的假象写进稿子。

## 阶段 3 — 产品化与规模化推广（What）

| 线 | 要求 |
|---|---|
| 逻辑（方案矩阵） | 把功能按**角色或业务环节**组织成方案矩阵（如一线执行者 vs 管理者），而不是平铺功能清单。 |
| 叙事（高潮） | 把局部胜利转化为标准化能力，武装核心业务单元。 |

里程碑要时间明确、可检查（如 Alpha / Beta / GA），并写清从试点进入推广的条件。

## 阶段 4 — 未来扩展与行动诉求（Next）

| 线 | 要求 |
|---|---|
| 逻辑（横向复制） | 说明能力如何复制到其他业务线，复制的前提条件是什么。 |
| 叙事（续章） | 从单个项目转向组织演进，邀请跨职能负责人加入。 |

必须落到具体的行动诉求：需要谁决定什么、需要什么资源与跨部门协同、时间要求、后续检查点。

## 四类典型问题

诊断时先按名字点出问题类型，再给依据与改法。

| 问题 | 表现 | 对应根因 |
|---|---|---|
| **自嗨式汇报** | 一上来就是「我们做了 X、Y、Z」，没有业务背景（S）与关键矛盾（C） | 缺 Why |
| **逻辑层级混乱** | 同一条列表里混放战略收益与战术任务（非 MECE） | 分类标准不统一 |
| **空中楼阁** | 直接提出宏大平台/战略，没有经过验证的 MVP 或快速见效的局部 | 缺 Where / How |
| **逻辑断层** | 章节之间没有时间（过去/现在/未来）或角色（一线→中层→总部）上的递进 | 叙事链断裂 |

## 三个自审问题

交付前用这三个问题反向检查，发现不通过就直接改稿，不停留在建议层面：

- **So What?** 开头能否让高管立刻看到底线价值？
- **Why This?** 为什么从这个场景起步，理由是否站得住？
- **Are They MECE?** 同层分类是否互斥且覆盖，是否把战略价值与执行任务混在一起？

## 一页纸模板

用户要空白模板或需要可直接填写的稿子时，使用下面的结构：

```markdown
# [项目名]：管理层汇报

## 1. 背景与核心价值（Why）
- 基线：当前业务状态与关注点
- 瓶颈：具体的运营痛点
- 突破：按数量/质量/速度拆解的价值主张（附 baseline 与口径）

## 2. 初始验证（How）
- MVP 范围：具体的试点场景
- 数据信号：试点中可量化的时间节省或质量提升

## 3. 规模化执行（What）
- 交付物：面向不同角色的标准化方案矩阵
- 里程碑：测试与全面推广的时间点

## 4. 下一步（Next）
- 扩展：可横向复制的业务线
- 诉求：需要的资源、预算或跨部门协同
```

## 重构混乱笔记的步骤

拿到一堆零散的项目进展时，按下面顺序处理：

1. 提取核心业务价值（SCQA 中的 A）；
2. 找出最小的成功验证案例（MVP）；
3. 把其余功能按角色/环节归入 MECE 方案矩阵；
4. 把全部内容映射到四阶段结构上。
